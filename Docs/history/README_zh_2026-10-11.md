## 先独自试，再三人合练

单人相机已实际连接，校准和动作控制仍待重试，三人流程仍待执行。**进入 Play 会自动启动摄像头预览，即使选中 TestSliders**；需要仅检查搭建时使用上面的无摄像头验证菜单。以下操作会使用摄像头。

- 先双击 `LaunchCamera.command`，允许摄像头权限。上半身模式只需肩和双手可见；按 **Q** 退出。退出这个独立追踪窗口后再进入 Unity，避免启动两个进程。
- 在 Unity 按 Play，选 **1 → Seated / upper body → Camera**。点击 **Set neutral pose (10 seconds)**，左手放腰部、肩膀放松，等待 Neutral pose saved。逐项测试；左手上下控制前进/后退，倾肩控制转向。
- P3 课程测试时选择 **3 → Upper body → Camera**。P1/P2/P3 按**非镜像预览画面从左到右**站定，确保肩、双手和头部全部可见，再校准；木头和水交互还需要本地 `gesture_recognizer.task`。中途人数或模式变化要重新校准。
- 分割任务在摄像头预览显示青色人体轮廓与 foreground 比例，独立于姿态追踪。它不识别谁是谁，也不用于证明大象生物学行为。可在独立相机测试中添加 `--no-segmentation` 比较开启前后。
- Camera 多人模式下，默认任何当前成员丢失都会暂停行走/转向；持续丢失要求重新校准。一个关节被挡与整个人丢失分开诊断。若 Python 预览显示 `RESET REQUIRED`，恢复固定站位，点击 **Reassign people** 并重新校准。位置匹配仍不能保证交叉后的真实身份；完整问题与处理见 [三人 bug 报告](Docs/THREE_PERSON_BUGS_中文.md)。需要立即停止时关闭 Enable locomotion 或退出 Play。

可保存场景、停止 Play 后运行 **Student Work → Run Single Person Camera Diagnostic**。它暂时选择 1 / Seated / Camera，使用真实相机；第 10 秒起检查并仅在动作就绪时校准，约 40 秒自动退出 Play，恢复保存的三人场景，只保存诊断 JSON，不保存照片或视频。保持两肩、双手入镜，双手腰高，先中立不动；坐姿模式的 LeftFootLift/RightFootLift 通道也来自手高，缺失提示不意味着必须拍到脚。

## 录制与数据

先分别演示每个人的控制，再录三人共同穿越障碍场。选 Camera、完成校准后点击 **Record performance**，结束点击 **Stop recording and save**。MP4 存在 `Recordings/<session>/performance.mp4`；录制目标为 10 fps、最高 1280×720，没有麦克风音轨。保持 Game 视图可见并播放检查成片。

StudentWork 的数据记录器单独启动和停止，导出 `Logs/Simulation/<UTC-id>/` 中的 CSV 和说明。记录的是人类代理驱动的虚拟轨迹、停留和空间关系，单位是 Unity 单位。老师的障碍场物体是装饰性几何，**没有碰撞器**；数据不声称测量了碰撞或真实大象反应。

本次滑块基本检查已实际导出 **14.253 秒、142 行轨迹**，数值均为有限值；标记 `data_kind = virtual_proxy_simulation`、`initialInputMode = TestSliders`、`received_frames = 0`。这是无摄像头的滑块模拟记录；目前另有单人相机连通诊断，成功校准后的表演轨迹与三人实验数据仍待采集。
