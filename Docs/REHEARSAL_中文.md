# 首次排练与演示流程

这些步骤尚未实际执行。录制前把结果填在 `TEST_LOG.csv`，不要预写“成功”。

## 先打通电脑

安装目标 Unity 编辑器并导入工程后，运行 Student Work → Prepare Team Scene。Console 不应有红色编译错误；打开 TeamPerformance 场景并确认 `_BeforeSavannah` 备份存在。使用老师的 DigiPhant → Savannah → Validate Shareable Environment 和 Validate Generator 菜单；验证会检查保存后的场景与资产，具体结果以 Console 为准。不要在 Play 中运行生成工具。

独自启动上半身摄像头测试，检查轮廓与骨架。退出独立进程后，在 Unity 的 Test sliders 逐项检查 rig，再选择 1 / Seated / Camera 并校准。做一小段录制，检查相机和大象都入画、MP4 能播放、时间长度合理。实际摄像头权限需用户允许。

## 三人逐项验证

1. 上半身站位、3 / Upper body / Camera、十秒中立校准。确认 P1-P3 与本人对应，并确认拳模型状态为 ready。
2. P1 演示左右前腿、慢速前进/停止、后退、左右转向；P2、P3 保持中立。
3. P2 演示左右后腿和尾巴；P1 保持行走与转向中立。
4. P3 演示头、鼻、双耳；P1、P2 保持中立。
5. 共同慢速移动，再按可见路径导航。先练转角再做整圈。停止后确认无持续漂移。
6. 测试 P1 暂时出画、单脚被遮挡、P2/P3 遮挡及恢复。对错误身份停止并重新分配、校准。

## 额外视觉任务的展示

用同一机位、光照和动作进行两次独立摄像头测试：

```bash
./LaunchCamera.command
./LaunchCamera.command --no-segmentation
```

每次结束先按 Q，避免并行进程。开启时检查轮廓贴合、多人合并、细肢缺失、背景误分与检测延迟；关闭时检查对照。Python 测试只证明软件路径可以运行，不能给出真人分割准确率。记录实际帧率、可见抖动及感受；分割增加推理工作量，不能声称没有性能影响。保存开启状态的 Unity 短片作为额外任务证据。

## 可检验的改进

候选：相机拍摄过远时，先保持控制参数不变，改善光照和站位，再用同样的动作比较校准成功率与身份丢失次数。记录前后条件和重复次数。若要改变平滑或死区，每次只改一个值，并同时观察漂移和停止延迟。只有实际对比完成后，反思才能写“一项测试过的改进”。

## 最终视频脚本建议（约 2-3 分钟）

- 开场：说明队名与 P1/P2/P3 姓名，展示站位和中立姿态。
- 各人约 15-20 秒：明确示范自己的控制，其他人保持中立。
- 集体段：启动轨迹数据记录，合屏录制实际障碍场尝试。保留必要的修正和失败，不能将剪辑冒充连续成功。
- 结束：停止视频与数据记录，检查 MP4 与 CSV，解释一项实测改进及一项局限。

参考录制器不收麦克风；若需讲解，可在展示现场口述或另录配音。Drive 放成片、映射说明与需要的大文件；Git 放实际演出场景、代码与配置。确认分享权限后填写 `team.json` 和 README 的提交链接。
